# 代码库扫描指引（doc-scan-guide）

> 本文件定义 thirdnet-doc-generator 技能在 **Step 2 扫描代码库** 时，按文档类型分别要采集的代码位置与结构化产出。
> **扫描阶段只读，绝不修改任何代码。** 推荐通过 Task 工具派发 Explore 子代理执行（主上下文只接收结构化摘要）。

## 核心原则：扫描是为了理解业务，不是搬运代码

读代码的目的是搞清**功能、业务流程、模块职责、角色权限、设计要点**，产出**业务摘要**供文档填充。**代码级细节（表名、字段类型/可空、索引名、接口路由、DTO 类型、权限串）一律不写入交付文档**——它们只在扫描阶段辅助你理解业务，必要时可在文档末尾"备注"中提示"详见 `spec.md`"。

简言之：**读的是代码，写的是业务。**

## 通用约定

- 派发 Explore 子代理时，prompt 必须自包含：指明**扫描根目录**、**目标文档集合（单类 / 多类 / 全 4）**、**下方对应采集项**，并要求**返回业务语言的结构化摘要**（表格形式），**不要粘贴源码或代码标识符**。
- 扫描产出 = **功能模块清单**（业务视角），供 Step 3 用户确认 / 裁剪。清单粒度以"一个业务模块"为一行（如"通知管理"），其下用业务语言描述功能、流程、对象、角色。
- 第三方依赖目录（`node_modules`、`bin`、`obj`、`.git`、`dist`）一律跳过。
- 后端代码通常在 `backend/{ProjectName}.Admin/` 或各微服务工程内；前端 Web 在 `frontend/web/`；小程序在 `frontend/minigram/`。若布局不同，先确认实际根目录再扫。
- **批量扫描（多类 / 全 4）**：4 类文档的代码源高度重叠（见 SKILL.md「各类型采集要点速查」矩阵），**只派 1 个 Explore 子代理**，把所选各类型的采集项合并为**并集**交给它，返回**一份**覆盖全部所选类型的结构化清单——不要为每类各扫一遍。

## 各文档类型采集项

> 表达式：从「代码位置」读懂「业务事实」，归纳为「文档用途」。

### 需求规格说明书

| 从代码读懂 | 代码位置（辅助理解） | 归纳为文档内容 |
|-----------|-------------------|---------------|
| 功能模块边界 | 前端 `src/views/{module}/`、路由表 | 模块清单（业务名称 + 用途） |
| 功能与能力 | 前端页面操作、Service 业务方法、权限注解 | 主要功能清单（功能名 + 能力/场景描述；优先级无法从代码得出则留待 Step 4 追问） |
| 角色与功能可见性 | 后端权限注解、前端权限指令 | 角色 + 谁能做什么（业务语言，不写权限串） |
| 业务流程 | Service 业务方法、调用链 | 业务流程概述（业务事件级流转，不写界面操作步骤） |
| 业务规则 / 字典 | 枚举字典、前端选项 | 字典取值与业务含义 |
| 校验规则 | 前端校验、后端 DTO 校验 | 必填 / 长度 / 范围（作为业务规则描述） |
| 注意事项 | 跨模块依赖、已知限制、扫描发现的边界与异常 | 注意事项素材（部分需用户确认） |

> 业务背景、优先级、验收标准**无法从代码得到**，留空待 Step 4 向用户追问。

### 系统设计文档

| 从代码读懂 | 代码位置（辅助理解） | 归纳为文档内容 |
|-----------|-------------------|---------------|
| 服务划分与职责 | `backend/` 各工程、启动配置 | 服务清单 + 职责定位（不标端口/连接串） |
| 核心数据对象与关系 | EF Core 实体、实体配置 | 数据对象 + 关系（概念层，不展开字段/索引） |
| 接口功能分组 | Controller、前端接口契约 | 按模块说明"做什么、何时触发、输入输出概念"（不写路由/类型） |
| 认证授权策略 | 认证配置、权限机制 | 认证方式与授权策略（概念，不贴代码/权限串） |
| 缓存用途 | 缓存调用点 | 缓存什么、为什么、失效策略（不写键名） |
| 后台任务用途 | 后台任务实现 | 任务业务用途与节奏 |
| 设计权衡 | 框架约束、技术选型 | 为什么这样设计（设计理念） |

### 用户手册

| 从代码读懂 | 代码位置（辅助理解） | 归纳为文档内容 |
|-----------|-------------------|---------------|
| 功能入口 / 菜单 | 路由表、菜单数据 | 菜单层级与入口 |
| 页面操作 | `src/views/{module}/index.vue` | 操作步骤（用页面实际按钮文案） |
| 字段标签 | Vue 模板 label、表格列标题 | 字段中文标签 |
| 选项文案 | 字典 / 枚举的中文标签 | 用户可见的选项文案 |
| 角色可见性 | 权限指令绑定的按钮 | 不同角色能做什么（业务语言） |
| 页面可截图性 | 前端项目类型（Admin 模板 / uniapp）、`.env` / `.env.{mode}` 中 `VITE_MOCK_ENABLED` 当前值、dev 启动命令、默认端口、是否存在 `src/mock/data/` | mock 截图可行性摘要（供 Step 3.5 判定主路径 / 降级） |

> 用户手册**禁止**出现技术词汇（权限串、路由、表名）。扫描得到的技术信息须转译为业务语言。
> 「页面可截图性」是用户手册**特有**的采集项——其它文档类型无需。其产出的「mock 截图可行性摘要」决定 Step 3.5 能否真正启动 mock 前端逐页截图，还是直接走降级。

### 测试用例文档

| 从代码读懂 | 代码位置（辅助理解） | 归纳为文档内容 |
|-----------|-------------------|---------------|
| 模块功能说明 | 菜单/页面业务用途、Service 业务方法、枚举字典含义 | 每个模块的功能说明（用途、主要能力、关键业务规则，业务语言，不写表名/路由） |
| 功能点 | 前端页面操作、业务方法 | 功能用例候选点（业务行为粒度） |
| 边界规则 | 字段类型 / 校验、选项 | 必填 / 长度 / 选项 边界用例 |
| 权限分支 | 权限注解 / 指令 | 无权限用例（入口隐藏 / 操作被拒） |
| 接口能力 | Controller、接口契约 | 接口能力用例（输入场景 + 预期行为，不写路由/类型） |
| 分页 / 查询 | 列表查询、筛选条件 | 分页与查询用例 |

## 扫描产出格式（返回给主上下文）

要求子代理**用业务语言**返回，便于 Step 3 呈现与 Step 4 填充——**不要返回表名 / 字段类型 / 路由 / 权限串**：

```markdown
## 功能模块清单（扫描根目录：...）

### 模块：[模块业务名]
- 职责：[这个模块做什么]
- 主要功能：[功能1（能力/场景）]、[功能2（能力/场景）]
- 业务流程：[业务事件1] → [业务事件2] → [业务事件3]（业务事件级流转，非界面操作步骤）
- 核心数据对象：[对象]（关键属性：...），与 [对象B] 的关系：...
- 接口能力：[查询列表]、[创建]、[修改]、[删除]、[查看详情]
- 角色：[角色A 可 ...]、[角色B 可 ...]
- 字典：[类型]（取值与业务含义）
- 注意事项：[边界情况、跨模块依赖、已知限制]
- 备注：[业务理解上的疑问 / 待用户确认点]
```

## 边界与限制

- 扫描**只读**：禁止任何 Write / Edit / 运行迁移 / 调用接口写操作。
- 若代码库为单体（无前后端分离布局），按实际目录调整采集位置，先与用户确认根目录。
- 扫描结果可能不完整（如部分功能仅有前端无后端，或反之）——在清单「备注」中标注缺失项，由 Step 3 用户补充。
- 若用户后续确实需要代码级清单（表结构/路由），那是 `spec.md` 的职责，引导其走 backend/frontend workflow，不要塞进交付文档。
