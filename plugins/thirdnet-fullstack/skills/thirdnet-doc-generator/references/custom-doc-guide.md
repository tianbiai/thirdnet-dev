# 自定义文档类型工作流（custom-doc-guide）

> 当用户要的文档**不在**默认 4 类（需求规格 / 系统设计 / 用户手册 / 测试用例）之内时，走本通用工作流。
> 常见自定义类型：部署运维文档、API 联调文档、版本发布说明、运维手册、评审纪要等（数据字典已固化为默认类型「数据库表结构文档」）。

## 工作流（与标准流程一致，仅"模板"改为共建）

1. **明确意图**：用 `AskUserQuestion` 问清——文档类型与名称、目标读者、覆盖范围、是否需要 Word 输出。
2. **共建大纲**：基于扫描得到的功能模块清单，与用户敲定章节结构（用下方「通用骨架」为起点，按类型裁剪）。
3. **扫描代码**：同标准 Step 2，按 [doc-scan-guide](doc-scan-guide.md) 中相关的采集项扫描（自定义类型通常只需其中一部分，如部署文档侧重配置 / 依赖，API 文档侧重接口）。
4. **用户确认范围**：同标准 Step 3。
5. **填充输出**：按共建大纲填充，占位符规则同标准流程；写入 `docs/{项目名}/{文档类型}-{YYYYMMDD}.md`，按需转 Word。

## 通用骨架

```markdown
# [项目名称] [文档类型]

> [一句话文档用途与受众。]

**文档版本**：[v1.0]　**编写日期**：[YYYY-MM-DD]　**编写者**：[git user]

---

## 1. 概述
[文档目的、适用范围。]

## 2. 范围
[覆盖的模块 / 服务 / 场景；明确包含与不包含。]

## 3. 正文
[按共建大纲组织的章节——根据文档类型灵活展开。]

## 4. 附录
[术语表、参考资料、关联文档、变更记录等。]

## 5. 备注
[待确认事项、扫描发现的差异。]
```

## 常见自定义类型速配

| 类型 | 重点采集项（见 doc-scan-guide） | 推荐章节 |
|------|------------------------------|---------|
| 部署运维文档 | 微服务清单、配置（appsettings）、后台任务、外部依赖 | 部署拓扑 / 配置管理 / 启停流程 / 监控告警 / 应急预案 |
| API 联调文档 | 接口清单、类型映射、认证流程 | 认证 / 接口清单（含示例入出参）/ 错误码 / 联调 checklist |
| ~~数据字典~~ | **已固化**为默认类型「数据库表结构文档」——见 [database-schema-template](database-schema-template.md)，走 Step 3.7 经 PostgreSQL MCP（dbhub）实时导出 | — |
| 版本发布说明 | git log / changelog、新增模块 | 版本号 / 新功能 / 优化 / 修复 / 升级注意 / 数据库变更 |

> 这些只是起点——最终章节以与用户共建的大纲为准。

## 注意事项

- 自定义类型**同样遵循"文档与代码同源"**：能扫到的填实，扫不到的追问，不臆造。
- 若自定义文档后续会反复生成，可将其大纲固化为新的 `references/*-template.md`，逐步纳入默认类型。
