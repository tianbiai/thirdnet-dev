# 合并与删分支检查清单

> 何时读：进入合并预检 / 冲突处理 / 删分支确认时。

## 合并预检清单（确认门 B 前）

纪律：合并前两边工作副本都提交到最新；整体合并会把分支上的所有代码（含废弃实验代码）带进主干。

- [ ] 原型分支 `{Project}-PT{r_base}` 工作副本 `svn status` 无输出（已全部提交）
- [ ] 主干 `{Project}` 工作副本 `svn status` 无输出（已全部提交）
- [ ] 废弃实验代码已清理（未被 spec 收录的 `views/` 页面、临时 Mock 数据、console 调试输出、注释死代码、孤儿页面）——整体合并会带进主干
- [ ] 已与前端协同确认工厂文件（`src/api/modules/**/*.ts`，如 `app/`、`manager/` 等子目录）的合并风险
- [ ] 已确认无其他人在主干并行写同一模块的真实实现（时序纪律）

预检通过后，触发确认门 B 执行 `svn merge`。

## 合并冲突处理清单（merge 后）

`svn merge` 后在主干工作副本执行 `svn status`，按此清单处理：

- [ ] 记录所有冲突标记 `C` 文件
- [ ] 重点检查工厂文件 `src/api/modules/**/*.ts`（高发冲突点）
- [ ] 逐个冲突文件人工解决（本技能不自动改业务代码）
- [ ] 解决后 `svn status` 确认无残留 `C` 标记
- [ ] `svn commit -m "merge: 合并原型分支 {Project}-PT{r_base} 到主干"`

## 删分支确认清单（确认门 C）

删除分支前确认：

- [ ] 该分支已合并回主干（mergeinfo 完整）
- [ ] 分支内无尚未合并的孤立改动
- [ ] 已确认不再需要回溯该分支

确认后触发确认门 C 执行 `svn delete`。
